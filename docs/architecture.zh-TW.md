# 公開架構：研究廣度與受控准入

Kairosys 把研究問題分配到多個專業視角，透過 typed evidence 與可追溯決策整合工作，再控制人類研究員最後能收到哪一種草稿。

![Kairosys 公開研究與准入流程](../assets/architecture.svg)

## 系統形狀

1. **研究問題。** 以公司、產業或估值問題定義要完成的工作。
2. **Agentic 協調。** 系統分配證據與分析責任，但不把模型文字當成來源權威。
3. **研究視角。** 基本面與財務建模、產業與供應鏈、市場脈絡與輔助技術訊號，以及估值與情境分析，提供互補的研究結果；催化劑、反證與分析師下一步則讓論點可採取行動、也可被推翻。
4. **Typed evidence 與 provenance。** 指標保留 value、period、unit 與 source identity；模型自行提出但沒有支持的來源主張，不會變成可信事實。
5. **持續研究脈絡與決策軌跡。** 先前證據與決策保持可追溯，讓後續工作能放回原本脈絡理解。
6. **兩層准入。** 完整性門檻處理致命的有效性失敗；效用分數另外衡量研究面向是否完成到足以使用。
7. **交給人判斷。** 結果只會是可編輯初稿、需複核初稿、僅保留脈絡，或完全不交付。這些是研究工作流意義，不是投資結論。

## 可執行案例讓什麼可被檢查

瀏覽器與 Python package 示範研究完成後的准入契約：provenance 重建、財務狀態分類、估值授權、rendered-report audit、完整性門檻、效用評分與交付。它不會用幾個只有外觀的 agents 假裝完整研究 runtime。

這個拆分是刻意的。較大的架構圖說明 Kairosys 協調什麼；可執行 slice 則證明研究廣度或漂亮文字，都不能蓋過破掉的基礎。

## 交付有四種意義

| 意義 | 研究員收到什麼 |
| --- | --- |
| Editable draft | 證據、狀態與 rendered wording 通過了示範中的檢查。 |
| Review-capped draft | 仍有可用材料，但可見標籤與信心上限要求研究員複核。 |
| Context-only draft | 背景脈絡可以保留，但沒有授權的目標值會移除。 |
| Withheld | 矛盾或不足的材料不會形成草稿。 |

這些是交付決策，不是投資結論。設計把研究員的判斷保留在最後一哩。

## 為什麼需要兩層

單一混合分數會產生錯誤誘因。數學無效的報告就算內容完整，也必須被硬性擋下；只涵蓋基本面與產業脈絡的報告則是另一種問題：它可能正確，卻還不足以成為完整研究。[兩層治理案例](two-layer-governance.zh-TW.md)把這兩種狀況與完整且乾淨的草稿放在一起比較。
