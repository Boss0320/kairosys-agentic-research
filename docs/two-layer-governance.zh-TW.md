# 兩層治理：正確性不能被平均掉

研究系統其實面對兩個不同的品質問題：

1. **這份產物有資格往下流嗎？** 完整性門檻處理硬性的有效性條件。
2. **這份產物已經夠有用嗎？** 效用分數衡量研究面向的完成度。

Kairosys 把兩個問題拆開。可執行機制位於 [`quality_governance.py`](../demo/kairosys_case/quality_governance.py)，對抗契約位於 [`test_quality_governance.py`](../tests/test_quality_governance.py)，[離線 dossier](../web/index.html)只呈現系統已提供的決策，不在瀏覽器重新計算。

## 契約

這個合成 dossier 對基本面、產業與供應鏈、市場脈絡、估值與情境、催化劑與反證，以及分析師下一步設定透明權重。一份乾淨草稿的效用分數至少要達到 `0.75`，才可能成為可編輯初稿。

當最終報告出現 blocking finding，或財務狀態不足時，完整性門檻就會失敗。此時原始效用分數仍會保留供讀者理解，但有效分數最高只能是 `0.40`。這讓規則非常清楚：只有事實基礎先過關，研究廣度才有意義。

這些權重屬於公開示範契約，不被描述為隱藏 runtime 的實作配方。
這個機制把「已完成哪些研究面向」當成 typed upstream input。它示範准入語意，不會假裝這個小型 package 能獨立完成或驗證每一個研究領域。

## 完整且乾淨

`ready_report` 完成全部六個面向。它的完整性門檻通過，效用分數是 `1.00`，有效分數維持 `1.00`，交付狀態是可編輯初稿。

這是正常成功路徑：研究夠完整、證據有支持、估值脈絡有授權，最終顯示的數學也一致。

## 完整但被阻擋

`rendered_math_conflict` 同樣完成六個面向，所以原始效用分數是 `1.00`。但顯示的目標值、forward EPS 與倍數彼此矛盾。rendered-report audit 產生 blocking finding，完整性門檻失敗，有效分數因此成為 `0.40`。

完整研究覆蓋仍保留供診斷，但不能抵銷致命錯誤；交付仍須複核。

## 淺但乾淨

`shallow_but_sound` 有受到支持的證據，而且沒有 audit finding，因此完整性門檻通過。但它只完成基本面與產業／供應鏈，效用分數與有效分數都只有 `0.35`。

這份草稿不會被錯誤標成完整研究。它因效用不足而維持需複核，所使用的 confidence cap 也與完整性失敗不同。

## 工程判斷

如果把所有訊號混成一個分數，就會掩蓋後兩種案例的差別：一個很廣但無效，另一個有效但不完整。分成兩層，才能保留兩種語意，也讓最終負責判斷的研究員看得懂交付狀態為何如此。
